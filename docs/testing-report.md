# 黑盒 GUI 测试报告(v1.0.0)

> 这份报告记录了应用成型的真实测试过程:17 组测试点、发现 8 个缺陷、修复 7 个、关闭 1 个。
> 测试方式:纯 GUI 黑盒(浏览器自动化模拟真实点击),配合导出 JSON 做数据交叉验证。

## 测试环境

- 视口:412×917(移动端),本地 HTTP 服务托管
- 方法:动作 → 截图 → DOM 快照交叉验证;数据正确性用"导出 JSON"核对

## 结果总览

| 类别 | 数量 |
|---|---|
| 测试点 | 17(主流程 6、交互反馈 6、边界 3、视觉 2) |
| 通过 | 13 |
| 缺陷 | 8(严重 2 / 中 3 / 低 3) |

## 缺陷与修复

### B1【严重】每周目标可无限刷能量
同一天内对"每周 4 次"目标重复点击打卡,每次都 +10 能量,而周计数按天去重不增长——能量可无限刷,等级与成就全部可被刷满。
**修复**:每周/每月目标增加"每天只记 1 次"守卫;完成度改按"当日是否打过卡"计算。

### B2【严重】补签会补到错误的目标
补签入口把 8/29 的签到补到了**当天(8/30)才创建**的目标上(该目标 8/29 根本不存在),污染连续天数;且未做补签操作时,入口日期会自行从 8/26 漂移到 8/29。
**根因**:缺口搜索遍历"当前全部目标",未校验目标创建日期。
**决策**:重构时评估后**移除补签功能**(打卡场景价值有限、修复成本高于收益),相关徽章一并移除(16 → 15 枚)。

### B3【中】关闭成功弹窗后无法撤销
"撤销本次打卡"只存在于打卡成功弹窗内,关闭后点击已完成卡片无任何响应。
**修复**:点击已完成卡片重新打开"今日已打卡"弹窗,提供撤销入口;撤销前校验记录存在,防止能量误扣。

### B4【中】长英文单词与按钮重叠
目标名含无空格长英文串时文本溢出卡片、穿透右侧按钮。
**修复**:`.goal-name { overflow-wrap: anywhere }`。

### B5【中】每周目标打卡后当日完成度不认账
打卡成功但"今日完成度 0%"。
**修复**:完成度统计口径改为"今天打过卡即计入"。

### B6~B8【低】
- 编辑抽屉关闭后输入框/图标/次数残留 → 统一 `resetSheetMode()` 复位
- 打卡弹窗关闭后仍残留于无障碍树 → 遮罩加 `visibility:hidden`
- 页面切换瞬间闪现旧数据 → 复测未复现,关闭

## 回归验证

缺陷修复后全部回归通过:每日/每周/计数型打卡、撤销、创建/编辑/删除、深色模式、主题切换、导入导出、清空与重置、刷新持久化。

## 经验

1. **"导出 JSON"是最好的测试探针**:UI 看起来对,不代表数据对(B2 就是靠导出数据坐实的)。
2. **可无限刷的奖励是逻辑漏洞**,不只是体验问题——它直接破坏等级/成就系统的意义。
3. 删除一个修复成本高于价值的功能,比留着隐患更好。
